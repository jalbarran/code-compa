# Spec 07: Native IDE HITL Interception & Agent Adapter

This specification defines how **Code Compa** automatically intercepts Human-in-the-loop (HITL) prompt interfaces generated by IDE extensions (e.g., AI agent panels asking for execution permission or selecting options) and routes them to the Mobile Companion app by wrapping standard IDE window APIs.

---

## 1. Overview & Goal

When AI agents run inside the IDE, they frequently request human confirmation before executing terminal commands or proceeding with code modifications. Normally, they trigger standard VS Code dialogs or message prompts. 

To make Code Compa transparently hook into *any* existing IDE agent without requiring agent-specific code changes, the extension wraps (monkey-patches) standard interactive VS Code APIs.

---

## 2. API Interception Strategy (Monkey-patching)

Upon activation, the Code Compa extension intercepts the target methods under the global `vscode.window` namespace.

```typescript
import * as vscode from 'vscode';

export function activateHITLInterception(context: vscode.ExtensionContext) {
  // 1. Intercept showInformationMessage
  const originalShowInfo = vscode.window.showInformationMessage;
  (vscode.window as any).showInformationMessage = async function(
    message: string,
    ...args: any[]
  ) {
    if (shouldRedirectToMobile()) {
      return await redirectInfoPromptToMobile(message, args);
    }
    return originalShowInfo.call(vscode.window, message, ...args);
  };

  // 2. Intercept showQuickPick
  const originalShowQuickPick = vscode.window.showQuickPick;
  (vscode.window as any).showQuickPick = async function(
    items: any[],
    options?: any,
    token?: any
  ) {
    if (shouldRedirectToMobile()) {
      return await redirectQuickPickToMobile(items, options);
    }
    return originalShowQuickPick.call(vscode.window, items, options, token);
  };

  // 3. Intercept showInputBox
  const originalShowInputBox = vscode.window.showInputBox;
  (vscode.window as any).showInputBox = async function(
    options?: any,
    token?: any
  ) {
    if (shouldRedirectToMobile()) {
      return await redirectInputBoxToMobile(options);
    }
    return originalShowInputBox.call(vscode.window, options, token);
  };
}
```

## 3. Payload Mapping & Event Conversion

### 3.1. `showInformationMessage` -> `RequestIntervention`
- **Source Parameters:** `showInformationMessage(message, "Approve", "Deny")`
- **Connect-RPC Payload:**
  - `type`: `"COMMAND_EXECUTION_REQUEST"` or `"CONFIRMATION"`
  - `title`: `"Action Required"`
  - `description`: The `message` string.
  - `options`: Maps the string parameters (e.g. `[{id: "Approve", label: "Approve"}, {id: "Deny", label: "Deny"}]`).
  - `allowsTextInput`: `false`.
- **Return Resolution:** When the mobile companion responds, the promise resolves to the selected option string (matching the selected button label).

### 3.2. `showQuickPick` -> `RequestIntervention`
- **Source Parameters:** `showQuickPick(["Option A", "Option B"], { placeHolder: "Select item" })`
- **Connect-RPC Payload:**
  - `type`: `"CHOICE_SELECTION"`
  - `title`: options.placeHolder || `"Select Option"`
  - `options`: Maps items to `DecisionOption` structures.
  - `allowsTextInput`: `false`.
- **Return Resolution:** Resolves to the selected item string or object.

### 3.3. `showInputBox` -> `RequestIntervention`
- **Source Parameters:** `showInputBox({ prompt: "Provide feedback" })`
- **Connect-RPC Payload:**
  - `type`: `"TEXT_INPUT_REQUEST"`
  - `title`: options.prompt || `"Feedback Required"`
  - `allowsTextInput`: `true`.
- **Return Resolution:** Resolves to the text input typed by the user on the mobile companion.

---

## 4. Blocking Flow & Fallback Checks

The interception must be non-destructive and transparent:

1. **State Check (`shouldRedirectToMobile`)**:
   - Return `true` only if the Mobile Companion is actively paired and connected (`status === 'CONNECTED'`).
   - If `false`, immediately fall back to the original VS Code native dialog to prevent blocking the developer at the desktop.
2. **Timeout Control**:
   - If the mobile client does not respond within a configured timeout limit (e.g. 60 seconds), the promise cancels the mobile request, displays a local notification, and falls back to the native desktop dialog.
3. **Cancellation Token Integration**:
   - If VS Code passes a `CancellationToken` to the API call, the extension aborts the mobile companion stream request if the cancellation token is triggered.

## 5. Verification & Testing

### 5.1. Simulated Extension Call Test
1. Create a mock extension or execute a command from the DevTools console:
   ```javascript
   const choice = await vscode.window.showInformationMessage(
     "Confirm git push to main?", 
     "Approve Push", 
     "Cancel"
   );
   console.log("User Choice: " + choice);
   ```
2. Confirm that **no dialog popup** appears on the desktop computer screen.
3. Verify that the mobile companion immediately shows a card with buttons **"Approve Push"** and **"Cancel"**.
4. Click **"Approve Push"** on the mobile phone.
5. Verify the DevTools console prints: `User Choice: Approve Push`.
