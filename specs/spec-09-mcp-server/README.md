# Spec 09: Model Context Protocol (MCP) Server

This specification outlines the architecture, tool definitions, and integration flow to expose Code Compa as an MCP (Model Context Protocol) server. This allows external AI agents (like Antigravity, Cline, Roo Code, Claude Desktop, etc.) to request human intervention via Code Compa's mobile application.

---

## 1. Goal & User Flow

The target behavior is to allow agents to securely request confirmation, multi-choice decisions, or text inputs from the human. The user receives these prompts as push/SSE notifications on their mobile companion app, responds, and the agent receives the answer synchronously.

### User Flow

1. An external AI agent (e.g. Cline or Antigravity) runs inside the IDE or developer machine.
2. The agent is configured to use the `Code Compa` MCP server.
3. When the agent is about to execute a high-risk operation (e.g. running a terminal command, editing critical configuration files) or explicitly requires human input, it invokes one of Code Compa's MCP tools.
4. The MCP server translates this tool call into a Connect-RPC request to the Code Compa Sidecar (`bridge-go`).
5. The Sidecar relays the request to the connected Expo mobile app.
6. The mobile app renders a premium Tamagui interface with the question/action details.
7. The developer selects "Approve", "Reject", writes an answer, or selects one of the options.
8. The response is routed back through the Sidecar to the MCP server, which resolves the tool call, returning the response payload to the agent.

---

## 2. Protocol & Transport

We will support **Stdio** transport for the MCP server. This is the simplest and most universally compatible method for local desktop clients (like Claude Desktop, Cursor, and VS Code extensions).

- **Executable:** The compiled Go binary (e.g. `/path/to/code-compa/packages/bridge-go/bridge`) called with the `--mcp` flag.
- **Communication:** Standard Input/Output (`stdin`/`stdout`).

---

## 3. Tool Definitions

The MCP server must expose the following three core tools to the AI client:

### `ask_human_confirmation`

Used when the agent wants to perform an action and requires a binary (Yes/No) confirmation.

- **Parameters:**
  - `prompt` (string, required): The description of the action to be confirmed (e.g. "Execute 'git push origin main'?").
  - `criticality` (string, optional): One of `"low"`, `"medium"`, `"high"`.
- **Returns:**
  - `confirmed` (boolean): `true` if approved, `false` if rejected.
  - `reason` (string, optional): Optional feedback if rejected.

### `ask_human_choice`

Used when the agent wants to present a list of options to the user.

- **Parameters:**
  - `question` (string, required): The question to ask (e.g. "Which test suite would you like to run?").
  - `options` (array of strings, required): The choices available to select from.
- **Returns:**
  - `selectedOption` (string): The exact string option selected by the user.

### `ask_human_input`

Used when the agent requires free-form text input from the user.

- **Parameters:**
  - `prompt` (string, required): Instruction of what the user needs to type (e.g. "Please enter your API Key prefix to verify").
  - `placeholder` (string, optional): Placeholder text.
- **Returns:**
  - `input` (string): The text written by the user.

---

## 4. Integration & Pairing

The MCP server needs to know where the Code Compa Go sidecar is running (specifically its localhost port).

- Upon startup, the MCP server reads the lockfile generated by the VS Code extension in `/tmp` using the workspace hash.
- The MCP server initializes a Connect-RPC client to talk to the Go sidecar.
- If no sidecar is running or no mobile device is paired, the MCP server returns an error response informing the agent that Code Compa is offline.

## 5. Configuration Example

### Antigravity (IDE Integration)

Antigravity integrates servers via standard environment mappings. To configure it to use Code Compa as a human gate:

- Configure the agent plugin setting in `.antigravity/mcp.json` (or matching host settings) as follows:

```json
{
  "mcpServers": {
    "code-compa": {
      "command": "/path/to/code-compa/packages/bridge-go/bridge",
      "args": ["-workspace-path", "/path/to/code-compa", "--mcp"]
    }
  }
}
```

### Claude Desktop (`config.json`)

```json
{
  "mcpServers": {
    "code-compa": {
      "command": "/path/to/code-compa/packages/bridge-go/bridge",
      "args": ["-workspace-path", "/path/to/code-compa", "--mcp"]
    }
  }
}
```

### Cursor or Cline Configuration

Registered via UI or global settings pointing to the same executable binary `/path/to/code-compa/packages/bridge-go/bridge` with the args `-workspace-path <workspace-path> --mcp`.
